DEBLUE FLUTTER APP - MEMORY OPTIMIZATION ANALYSIS (QUICK SUMMARY)
================================================================================

PROJECT OVERVIEW:
- Total Dart Files: 24
- Total Lines of Code: 3,146
- Main Asset: 9.6 MB Linux binary
- State Management: GetX Framework
- Architecture: MVC with Service Layer

================================================================================
CRITICAL ISSUES (Fix Immediately)
================================================================================

1. HttpClient Memory Leak - HIGH SEVERITY
   Location: backend_process_service.dart:83-107
   Impact: 2-5 MB memory leak during startup (20+ clients created)
   Fix: Use singleton HttpClient instance
   
2. Permanent HomeController - HIGH SEVERITY
   Location: home_binding.dart:8
   Impact: 100+ KB held in memory unnecessarily after navigation
   Fix: Remove "permanent: true" flag
   
3. StreamController No Backpressure - HIGH SEVERITY
   Location: bluetooth_event_service.dart:16-19
   Impact: Memory accumulates during rapid events (50+ per second)
   Fix: Add debouncing/throttling or use rxdart ReplaySubject
   
4. WebSocket Reconnect Leak - MEDIUM SEVERITY
   Location: bluetooth_event_service.dart:23-47
   Impact: Multiple reconnect timers can accumulate
   Fix: Store reconnect timer and implement exponential backoff

================================================================================
HIGH PRIORITY ISSUES (Implement This Week)
================================================================================

5. TextEditingController Not Disposed
   Location: settings_view.dart:12-14
   Impact: Resource leak on every rebuild
   Fix: Convert to StatefulWidget, dispose in dispose()

6. Debounce Timer Inefficiency
   Location: home_controller.dart:76-80
   Impact: 50+ timers created/destroyed per second during scan
   Fix: Use proper Debounce implementation

7. List Item Keys Missing
   Location: home_view.dart (GridView.builder & ListView.separated)
   Impact: Poor list performance, memory thrashing
   Fix: Add ValueKey(device.path) to item builders

8. Large Binary Asset Bundled
   Location: assets/bin/linux/deblue (9.6 MB)
   Impact: App size + memory during extraction
   Fix: Consider on-demand download at first run

================================================================================
MEDIUM PRIORITY ISSUES (Next Sprint)
================================================================================

9. Excessive Obx() Rebuilds
   Location: home_view.dart (16 Obx blocks)
   Impact: Entire device grid rebuilds on any observable change
   Fix: Replace with targeted GetBuilder calls
   
10. ListView/GridView Not Optimized
    Location: home_view.dart
    Impact: Keeps too many offscreen widgets in memory
    Fix: Set addAutomaticKeepAlives: false, specify cacheExtent: 500
    
11. Gradient Recomputation
    Location: app_shell.dart:29-55
    Impact: Color objects created on every build
    Fix: Extract gradient to theme or cache

12. Unused Code Cleanup
    Location: settings_controller.dart (TODO counter)
    Impact: Minor memory waste
    Fix: Remove or implement SettingsController
